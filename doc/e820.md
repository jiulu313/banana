好，继续第 23 课：**开始做真正的物理内存管理**。

我们前面的：

```c
#define HEAP_START 0x200000
```

其实只是“假设 2MB 以后是空闲的”。

真正的 OS 不能这么做，因为不同机器内存布局不一样，某些区域可能被 BIOS、设备、ACPI 等占用。

所以接下来要解决：

> **banana 怎么知道哪些物理内存可以用？**

传统 BIOS 环境里，常用办法是调用：

```text
INT 15h, EAX = E820h
```

获取 BIOS 提供的内存地图。

我们先讲清楚概念，不急着一下写完整。

BIOS 返回的内存地图大概会告诉我们：

```text
起始地址        长度            类型
0x00000000      0x0009FC00      可用
0x0009FC00      0x00000400      保留
0x000F0000      0x00010000      保留
0x00100000      0x03F00000      可用
...
```

其中最重要的是：

```text
type = 1
```

通常表示：

> 可用 RAM

其他类型我们先认为不可用。

最终 banana 会把物理内存按：

```text
4 KB
```

切成很多页：

```text
page 0
page 1
page 2
...
```

因为以后 x86 分页也是以 4KB 为基本单位。

例如 16MB RAM：

```text
16 MB / 4 KB
= 4096 pages
```

我们可以用一个 bitmap 来记录每一页是否被占用。

比如：

```text
bit = 0  空闲
bit = 1  已使用
```

于是：

```text
page 0  -> 1
page 1  -> 1
page 2  -> 0
page 3  -> 0
...
```

然后实现：

```c
void *pmm_alloc_page(void);
void pmm_free_page(void *addr);
```

这才是真正意义上的“物理页分配器”。

不过第一步得先让 stage2 在实模式下拿到 E820 内存地图。

因为：

```text
INT 15h
```

是 BIOS 服务，进入保护模式后我们就不方便再调用了。

所以流程会变成：

```text
stage2 实模式
↓
调用 BIOS E820
↓
把内存地图保存到一块固定内存
↓
进入保护模式
↓
跳到 C kernel
↓
kernel 读取这份内存地图
↓
建立 PMM
```

这一课我们先定义传递位置。

暂时规定：

```text
0x5000
```

保存 E820 entries，

```text
0x4FF0
```

保存 entry 数量。

也就是：

```text
0x4FF0  -> entry count

0x5000  -> entry 0
0x5018  -> entry 1
0x5030  -> entry 2
...
```

为什么每项 24 字节？

因为 E820 常见扩展结构是：

```c
struct e820_entry {
    unsigned long long base;
    unsigned long long length;
    unsigned int type;
    unsigned int acpi;
};
```

也就是：

```text
8 + 8 + 4 + 4 = 24 bytes
```

下一步我们会在 `stage2.asm` 里写一个：

```asm
detect_memory:
```

循环调用 BIOS：

```asm
int 0x15
```

拿到整张内存地图。

等这一步跑通后，我们会先让 kernel 把检测结果打印出来，例如：

```text
E820 entries: 6

base=0x00000000
length=0x0009FC00
type=1

base=0x00100000
length=0x03EF0000
type=1
```

这样你能真正看到 QEMU 虚拟机提供给 banana 的物理内存布局。
